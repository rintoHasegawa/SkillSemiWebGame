# ロビー仕様 (Lobby Specification)

## タイトル画面 (Title Screen)

### 画面構成 (Screen Layout)

- 背景: タイトル画像（title.png）を全画面表示する
- 初期状態: 「- TAP TO START -」が点滅表示される
- タップ後: 入力フォームがフェードインで表示される

### 入力項目 (Input Fields)

- プレイヤー名: テキスト入力（必須）
- ルームID: テキスト入力（必須）

#### 入力の受け入れ条件 (Input Constraints)

プレイヤー名・ルームIDに共通の条件とする．

- 前後の空白は除去したうえで判定する（除去後に空になる入力は受理しない）
- 最大長: **32 文字**（`PLAYER_NAME_MAX_LENGTH` / `ROOM_ID_MAX_LENGTH`）
  - 文字数は UTF-16 コードユニット数で数える．入力欄の `maxlength` 属性と同じ基準にすることで，クライアントの入力制限とサーバ検証の判定がずれないようにする
  - ※ 絵文字などのサロゲートペア文字は 1 文字で 2 文字分と数える
- 使用できない文字: 制御文字・改行・行区切り・不可視の書式文字（ゼロ幅スペース，双方向制御文字，BOM 等）・単独サロゲート
  - サーバログへの改行注入と，不可視文字による名前の偽装を防ぐことを目的とする
  - 日本語・絵文字は使用できる．絵文字の連結に用いる ZWJ（U+200D）は例外的に許可する
  - ※ タグ文字（U+E0020〜U+E007F）を用いる一部の旗絵文字（イングランド旗等）は書式文字を含むため受理しない
- 判定式は shared（`domains/room/joinInput.ts`）に集約し，クライアントの入力欄制限とサーバの受信検証で共有する

### 入室操作 (Join Operation)

- 「GAME START」ボタンを押すとサーバーへ入室リクエストを送信する
- 送信中はボタンが「接続中...」表示になり，非活性化される
- 両方の入力が空でない場合のみボタンが活性化される

### 入室拒否 (Join Rejection)

サーバーから拒否された場合，エラーメッセージを表示する．

- 満員（full）: ルームの最大人数に達している
- 重複（duplicate）: 同じ接続IDで既に入室済み
- ゲーム中（playing）: ルームが既にゲーム中である
- 不正な入力（invalid）: プレイヤー名またはルームIDが入力の受け入れ条件を満たさない
  - 受信ペイロードを処理せず破棄するだけでは，クライアント側でタイムアウト（誤解を招く表示）になるため，拒否理由として通知する
  - 通知する `roomId` は空文字とする（未検証の受信値をそのまま返さない）

## ロビー画面 (Lobby Screen)

### 画面レイアウト (Screen Layout)

- 左上: 「タイトルへ戻る」ボタン
- 上部中央: ルームIDと「(待機中)」ステータス表示
- 左半分: ゲーム操作パネル（スタートボタン or 待機メッセージ）
- 右半分: 参加プレイヤーリスト

### ホスト（オーナー）向け表示 (Host View)

#### ゲーム設定（歯車ボタンからモーダルで開く） (Game Settings)

- 目標人数: 4人刻みで選択（最小: 現在の参加人数を4の倍数に切り上げ，最大: 100）
  - 不足分はBotが補充される
  - 目標人数は4チームへ均等分割するため，**4の倍数であることを仕様とする**
  - 判定式は shared（`domains/room/targetPlayerCount.ts`）に集約し，UIの選択肢生成とサーバ検証で共有する
  - サーバの受け入れ条件は「4 ≤ 目標人数 ≤ ルーム最大人数 かつ 4の倍数」とする．「現在の参加人数以上」はUI表示上の制約であり，検証中に参加人数が減るレースがあるためサーバでは強制しない
  - 条件を満たさない値は丸めず，設定更新全体を破棄してサーバログに記録する
  - ※ ルーム最大人数（`MAX_PLAYERS_PER_ROOM`）は 4 の倍数であることを前提とする（4 の倍数でない値に変更すると，UIの選択肢が上限を超えサーバに破棄される組み合わせが生じ得る）
- フィールドサイズ: プリセットから選択
  - SMALL: 推奨 4〜20人
  - MEDIUM: 推奨 20〜40人（既定値）
  - LARGE: 推奨 40〜70人
  - XLARGE: 推奨 70〜100人
- チーム割り当て方式: ランダム / プレイヤーが選択

#### 操作ボタン (Operation Buttons)

- 「ゲームスタート」ボタン: 押すと確認モーダルが表示される
- 「ルールを見る」ボタン: ゲームルール説明モーダルが開く

### メンバー（非オーナー）向け表示 (Member View)

- 「ホストの開始を待っています...」メッセージ
- ホストが設定したゲーム人数・フィールドサイズ・チーム割り当て方式の表示
- 「ルールを見る」ボタン

### チーム選択 (Team Selection)

- チーム割り当て方式が「プレイヤーが選択」の場合に有効になる
- 選択肢: ランダム / 赤チーム / 青チーム / 緑チーム / 黄チーム
- 満員のチームを選択した場合，「このチームは満員です」メッセージが3秒間表示される
- 「ランダム」の場合は自動モードと同様にサーバーが割り当てる

### プレイヤーリスト (Player List)

- 表示内容: プレイヤー名，オーナーマーク（王冠），自分マーク（緑丸）
- チーム選択モード時: 選択チーム名をチームカラーで表示する
- ソート順: 入った順（既定） / チーム順 / 名前順
  - チーム順はチーム選択モード時のみ選択可能
- ヘッダー: 「参加プレイヤー (現在人数/最大人数)」

### ゲーム開始確認モーダル (Game Start Confirmation Modal)

- ホストが「ゲームスタート」を押すと表示される
- 確認ボタンとキャンセルボタンがある
- 確認を押すとサーバーにゲーム開始リクエストを送信する
- サーバー側でゲーム開始に失敗した場合，ルームは待機状態に戻り，ルーム状態の同期（ROOM_UPDATE）で全メンバーに反映される（専用の失敗通知イベントはない）

### 設定のリアルタイム同期 (Real-time Settings Sync)

- ホストが設定を変更すると，サーバー経由で全メンバーに即時反映される
- メンバー側では設定項目は閲覧のみ（変更不可）
- 設定はルームが保持し，ホストが切断してオーナーが移譲されても引き継がれる（`ownerId` のみ差し替わり，目標人数・フィールドサイズ・チーム割り当て方式は保持される）
- 新しいホストのクライアントは，オーナーを獲得した時点でルームの現在設定を自分のローカル設定へ取り込む．取り込みが完了するまで設定更新（`LOBBY_SETTINGS_UPDATE`）を送信しない
  - 一度も設定を操作していない新ホストのローカル既定値でルーム設定が巻き戻ることを防ぐため
- 設定更新の送信はホスト自身が設定を変更したときに限る．同じ値の再送は行わない
  - ただしルームの目標人数が未設定（`targetPlayerCount` が未定義）の場合は，メンバー側の表示を「未設定」のまま残さないよう初期値を 1 度だけ送信する
- ゲーム開始要求（`START_GAME`）には，ホストのローカル設定を採用する．設定変更直後で `ROOM_UPDATE` がまだ返っていない時間帯ではローカル側が新しいため
  - ルーム設定の取り込みが未完了の場合に限り，ルームの現在設定を採用する
